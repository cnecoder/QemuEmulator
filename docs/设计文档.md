## 1. 系统目标与需求映射

| 需求 | 实现机制 | 章节 |
|---|---|---|
| x64 宿主上运行 ARM64 Linux 被测软件 | QEMU `aarch64-softmmu` 全系统模拟（TCG，无 KVM 依赖） | §3.6 |

| AI 自闭环 | envctl 统一 CLI + pytest 32 例 + junit 报告 | §3.7 |

## 3. 组件设计

### 3.1 usb-wmodem 设备模型（p1/device/dev-wmodem.c）

基于 `hw/usb/dev-serial.c` / `dev-network.c`（LGPL）改编，QEMU ≥10/11 头文件布局。

#### 3.1.1 USB 描述符布局（硬契约）

| 接口号 | 类/子类/协议 | 功能 | guest 驱动 | guest 设备 | 端点 |
|---|---|---|---|---|---|
| **in00** | 0xFF/0x00/0x00 | AT 串口 | option（new_id 注入 VID/PID） | ttyUSB0 | bulk IN 0x81 / OUT 0x01 |
| **in01** | 0xFF/0x00/0x00 | diag 串口 | option | ttyUSB1 | bulk IN 0x82 / OUT 0x02 |
| **in02** | 0xFF/0x00/0x00 | nmea 串口（预留） | option | ttyUSB2 | bulk IN 0x83 / OUT 0x03 |
| **in03** | 0xEF/0x04/0x01 | RNDIS 控制（含 IAD/Union/ACM 功能描述符） | rndis_host | 网口 | INT IN 0x84 |
| **in04** | 0x0A/0x00/0x00 | RNDIS 数据 | rndis_host | usb0/enx… | bulk IN 0x85 / OUT 0x04 |

- 设备级：`bcdUSB=0x0200`，`bDeviceClass=0xEF/0x02/0x01`（IAD 复合），EP0=64，bulk=512
- VID/PID 为 QEMU 属性（默认 0x1234/0x5678），per-instance 描述符副本实现动态替换
- **in 字段是被测软件的识别契约，改接口顺序必须同步被测软件**
- 串口接口 subclass/protocol 取 0x00：option 驱动只查 0xFF 类，同时避开 usbtouchscreen 对 0xFF/0xFF/0xFF 的整类抢占（仍需黑名单，见 §4 ADR-3）

#### 3.1.2 数据通路

- **串口（3 路独立）**：guest ↔ bulk 端点 ↔ 每端口环形缓冲（4KB）↔ `CharFrontend` chardev（unix socket）。AT 场景引擎作为 chardev 对端。IN 空时 NAK，有数据时 `usb_wakeup` 唤醒。
- **RNDIS 数据面**：guest 帧带 `rndis_packet_msg_type` 头经 data OUT（nr4）→ 解析 → `qemu_send_packet` → netdev；反方向 netdev receive → RNDIS 封装 → IN。**收包门控**：`rndis_state == RNDIS_DATA_INITIALIZED`（由 rndis_host 设置 packet filter 触发）且 `in_buf` 空闲（单包缓冲，忙时返回 0 让 slirp 重试）。
- **RNDIS 控制面**：`SEND_ENCAPSULATED_COMMAND`（wIndex 必须 = 3）→ `rndis_parse`（INIT/QUERY/SET/RESET/KEEPALIVE）→ 响应经 `rndis_resp` 队列由 status INT 端点（nr4）驱动投递。

#### 3.1.3 状态迁移与快照

vmstate 包含：`VMSTATE_USB_DEVICE`（USB 核心 state/addr/setup——**缺失则 loadvm 后首包断言崩溃**）、串口 3×(ptr/used/buf)、RNDIS 全量状态（state/medium/speed/media_state/filter/in/out 缓冲）。rndis_resp 队列不迁移（瞬时响应，恢复后由重发机制覆盖）。

#### 3.1.4 QEMU 版本适配

11.x 相对 9.x 的适配点：include 布局（`hw/usb/usb.h`、`hw/core/qdev-properties*.h`）、`CharBackend→CharFrontend`、class_init data 参数 `const`、Property 数组**移除 END_OF_LIST 且必须 const**（编译期校验最后元素非 NULL）。适配仅涉及 include 与类型名，逻辑零改动。

### 3.2 场景引擎（p1/engine/wm_scenario_engine.py）

- **状态模型**：`fun(0/1) × sim(absent/ready/pin) × reg(none/searching/denied/home/roaming) × data(attached/detached)`，派生量 `_reg_stat()`（TS 27.007 stat 值）与 `_data_attached()`。
- **AT 服务**：行缓冲解析（CR/LF），`ATE` 回显模式，命令分发表；SIM 缺失时按规范返回 `+CME ERROR: 10`。支持 `AT+WMSTAT` 厂商扩展直读状态。
- **URC**：`AT+CEREG=<1|2>` / `AT+CGEREP=1` 订阅后，状态切换自动下发 `+CEREG: <stat>` / `+CGEV: ME DETACH|ATTACH`；另有控制 API 直接注入任意 URC 行。
- **控制 API**：unix socket（`run/engine-<dev>.sock`），行 JSON 请求/应答。命令：`status / scenario / set_signal / inject_urc / set_link / set_delay`。
- **QMP 集成**：按需连接（连接→执行→断开），不长期占用 `qmp.sock`（快照脚本需要它）。

### 3.3 数据面分层

| 层 | 网段/通道 | 用途 | 断网手段 |
|---|---|---|---|
| 管理网 n0（virtio） | slirp 10.0.2.0/24 | SSH/文件/云包安装 | 不断（保持可管理性） |
| 蜂窝数据面 cell（usb-wmodem RNDIS） | slirp 10.0.3.0/24 | 被测软件的"蜂窝"上网 | AT 层（CGATT=0）+ QMP `set_link cell off`（真断） |
| 设备间链路 l1/l2（virtio，集群） | UDP socket 经 wm_linkd | 设备互联 | wm_linkd 损伤参数（真断：loss=100 或清空转发） |

弱网：QEMU `filter-buffer` 对象（`interval=<µs>` 定时冲刷）运行时挂到蜂窝 netdev——**QEMU 无 filter-delay 对象**（实测），buffer 的定时冲刷等效产生延迟。

### 3.4 链路损伤代理 wm_linkd（p1/cluster/wm_linkd.py）

- **拓扑**：每条链路两个 UDP socket（分别绑定 A/B 的“发送目标端口”），QEMU 双方以 `udp=<对端入口>`、`localaddr=<自身接收>` 接入。代理收到一侧的帧 → 损伤管线 → 发往另一侧 QEMU 的 localaddr。
- **损伤管线**（按序）：丢包（概率）→ 时延（delay±jitter，asyncio 定时）→ 带宽（每 (链路,方向) 独立令牌桶，rate=0 不限）。
- **独立性**：每链路独立参数与统计（`a2b_*/b2a_*` 六计数器），互不串扰。
- **控制**：unix socket 行 JSON：`set/clear/clear_all/status`，参数 `delay_ms/jitter_ms/loss_pct/bw_kbps`。

### 3.5 集群编排

| 设备 | 容器名 | SSH | QMP/AT/引擎套接字 | overlay | 链路 MAC |
|---|---|---|---|---|---|
| A | p1-vm-a | 2223 | qmp-a / at0-a / engine-a | run/disk-a.qcow2 | a1:00:01 / a2:00:01 |
| B | p1-vm-b | 2323 | qmp-b / at0-b / engine-b | run/disk-b.qcow2 | b1:00:01 / b2:00:01 |

- overlay 从主 overlay 克隆（避免每设备重复慢速置备）；链路 IP 由编排脚本按 MAC 定位接口静态配置（link1=10.0.100.x，link2=10.0.200.x）。
- 扩展到 N 设备：设备表加行 + 链路定义加组，wm_linkd 天然支持多链路。

### 3.6 虚拟机启动（双模式）

- **容器模式**（WSL2/宿主默认）：QEMU 为分离容器前台进程，**同路径挂载**（`-v $P1_DIR:$P1_DIR`），消除了历史 `/work` 与真实路径的双路径问题。
- **QEMU_DIRECT=1**（CI 容器内）：nohup 直跑 QEMU，pid 记录 `run/qemu.pid`，`vm_stop.sh` 自适应停机。

### 3.7 自动化层

- **envctl**：统一入口（up/provision/verify/snap/restore/engine/scenario/set_*/inject_urc/at/status/stop/test）。
- **pytest**：conftest 提供 `lab`（session 级环境拉起，幂等）/`modem`（场景句柄+自动恢复 normal）/`at`（带重试与有效性判定的 AT 调用）fixtures；32 例分四组。
- **稳定性设计**：at_client 非阻塞写+重试、打开端口先收取残留（URC 不丢）、OK/ERROR+静默退出判定、无效响应自动重试、TCG 抖动以重试吸收。

## 4. 关键设计决策记录（ADR 摘要）

| ADR | 决策 | 依据（实测） |
|---|---|---|
| 1 | USB 仿真选路线 C（QEMU 设备模型），放弃 U（内置设备身份不符）/ G（内核 gadget 需宿主配合） | 路线 C 单进程、零内核依赖、全环境可移植；32 例回归全绿 |
| 2 | RNDIS 控制接口取 `0xEF/0x04/0x01` | `rndis_host` 通用匹配实测别名；避开 cdc_acm（0x02/0x02/0xFF 会被其抢占） |
| 3 | usbtouchscreen 黑名单 + rmmod | 实测其认领 0xff/0xEF/0x0A 全部接口 |
| 4 | 固件 pin 至 edk2 2024.02（`p1/compat/QEMU_EFI.fd`，随仓库分发） | edk2 2025.11（26.04）在 QEMU 9.2/11.1.3 上均挂死于 DXE；2024.02 正常 |
| 5 | `-global virtio-pci.romfile=` 全局禁用 virtio ROM | 源码构建无 ipxe ROM，11.1.3 的 virtio 设备默认请求 efi-virtio.rom 导致启动即退 |
| 6 | 蜂窝 slirp 独立网段 10.0.3.0/24 | 双 slirp 同网段 → guest 双接口重复 IP → ARP/路由污染 |
| 7 | 快照：QMP snapshot-save（写）+ CLI loadvm（读）+ 设备 vmsd 必含 VMSTATE_USB_DEVICE | pflash 不支持快照；缺 USB 核心状态则恢复后断言崩溃 |
| 8 | 弱网用 filter-buffer（interval） | QEMU 无 filter-delay 对象（实测） |
| 9 | 双模式启动 + 同路径挂载 | CI 容器无 docker；消除双路径分歧 |

## 5. 版本与兼容性策略

| 组件 | 当前版本 | 升级方式 |
|---|---|---|
| 容器基座 | ubuntu:26.04 | 改 Dockerfile FROM → rebuild |
| QEMU | 11.1.3（`QEMU_VER` 参数） | 下载新版 tarball 到 `p1/src/` → `QEMU_VER=<ver> 10_build.sh` → 冒烟（`-device help` 含 usb-wmodem + 25 号验收）→ 通过后默认启用 |
| 固件 | edk2 2024.02（仓库资产） | edk2 升级需先过 §9 冒烟；不兼容则维持 pin |
| guest | Ubuntu 24.04 (noble) cloud image | `01_fetch_image.sh` 换 URL；镜像换版后 overlay 需重建并重新置备 |

产物路径策略：编译产物复制到 **`p1/build/qemu-custom/`**（与版本号解耦），消费方（20_run_vm.sh/CI）只认稳定路径。

## 6. 接口契约汇总

1. **USB 身份契约**：VID/PID 可配；接口布局与 in 字段（§3.1.1）为被测软件识别依据。
2. **AT 语义契约**：引擎应答遵循 TS 27.007 子集；SIM 缺失 → `+CME ERROR: 10`。
3. **控制 API 契约**：行 JSON 请求/应答（见使用手册 §3、§4）。
4. **网络契约**：管理网 10.0.2.0/24（SSH 2223）、蜂窝网 10.0.3.0/24（DHCP 10.0.3.15）、集群链路 10.0.100.0/24 与 10.0.200.0/24。
5. **端口契约**：SSH 2223（单机）/2223+2323（集群）；linkd 入口 4001-4004；接收 4101-4104。
