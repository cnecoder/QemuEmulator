# 用户使用手册 —— ARM64 + USB 蜂窝模块模拟环境

> 版本：v1.0（2026-11）。面向使用本环境做测试/开发的工程师与 AI 代理。
> 部署与安装见《部署文档》；设计原理见《设计文档》；快速排错见 README §9。

## 1. 五分钟上手

```bash
cd QemuEmulator
python3 p1/envctl.py status      # 看环境状态
python3 p1/envctl.py up          # 没起就拉起（已起则幂等返回）
python3 p1/envctl.py verify      # 设备级验收
python3 p1/envctl.py test        # 全量回归（约 8 分钟）
```

登录虚拟机排查：`ssh -i p0/keys/id_ed25519 -p 2223 test@127.0.0.1`

被测软件视角（虚拟机内）：
- AT 口：`/dev/ttyUSB0`（in00），diag/nmea：ttyUSB1/2（in01/02）
- 蜂窝网卡：`enx525400123457`（in03/04，DHCP 10.0.3.15）
- 设备身份：`AT+CGMI`→WModem、`AT+CGMM`→WM650-GL、USB VID/PID 1234:5678

## 2. envctl 命令参考

所有命令幂等可重复执行。`python3 p1/envctl.py <子命令> ...`

### 2.1 生命周期
| 命令 | 说明 |
|---|---|
| `up [--fresh]` | 启动虚拟机+等待+置备。`--fresh` 丢弃 overlay 得到全新机器（首次约 25 分钟含 cloud-init 置备，之后冷启约 5 分钟） |
| `stop` | 停虚拟机与引擎 |
| `status` | VM/引擎/modem 状态总览 |
| `provision` | 重新置备（驱动绑定/节点防护，幂等） |

### 2.2 快照
| 命令 | 说明 |
|---|---|
| `snap <tag>` | 整机存档（约 2 秒） |
| `restore <tag>` | 读档复位（约 8 秒，含 SSH 恢复确认） |

推荐工作流：验收全绿后 `snap stable`；每轮测试前 `restore stable`（避免状态残留，且比冷启动快 50 倍）。

### 2.3 验收与回归
| 命令 | 说明 |
|---|---|
| `verify` | 设备级验收（15 断言，`P1_ALL_GREEN`） |
| `test [pytest 参数]` | 全量回归 32 例（junit 报告 → `p1/reports/junit.xml`） |
| `test tests/test_scenarios.py -k no_sim` | 子集运行 |

### 2.4 场景注入（详见 §3）
`engine on|off` · `scenario <name>` · `set_signal <0-31>` · `set_link on|off` ·
`set_delay <ms>` · `inject_urc '<行>'`

### 2.5 AT 调试
`at '<AT 命令>'` —— 例：`envctl.py at "AT+CSQ"` → `+CSQ: 20,99 OK`

## 3. 场景引擎 API 参考

传输：unix socket `p1/run/engine.sock`（单设备）/ `engine-a.sock`、`engine-b.sock`（集群）。
协议：每行一个 JSON 请求 → 一行 JSON 应答。

### 3.1 命令一览

| 请求 | 效果 |
|---|---|
| `{"cmd":"status"}` | 返回完整状态快照 |
| `{"cmd":"scenario","name":"..."}` | 切换场景：`normal` / `no_sim` / `searching` / `denied` / `detached` / `offline` |
| `{"cmd":"set_signal","rssi":N}` | 0-31（`AT+CSQ` 联动） |
| `{"cmd":"set_link","up":bool}` | 蜂窝链路真通断（QMP set_link，不只改 AT 状态） |
| `{"cmd":"set_delay","ms":N}` | 蜂窝口弱网延迟（filter-buffer；0=清除） |
| `{"cmd":"inject_urc","line":"..."}` | 向 AT 流注入任意 URC 行 |

### 3.2 场景语义表

| 场景 | SIM | 注册 | 附着 | 蜂窝链路 | 典型 guest 观测 |
|---|---|---|---|---|---|
| normal | ready | home | attached | up | `+CEREG: 0,1`、`+CGATT: 1`、上网正常 |
| no_sim | absent | none | detached | 不变 | `AT+CPIN?`→`+CME ERROR: 10`、URC `+CEREG: 0` |
| searching | ready | searching | detached | 不变 | `+CEREG: 0,2` |
| denied | ready | denied | detached | 不变 | `+CEREG: 0,3` |
| detached | ready | home | detached | **down** | `+CGATT: 0`、URC `+CGEV: ME DETACH`、上网中断 |
| offline | ready | none | detached | **down** | `AT+CFUN?`→`+CFUN: 0`（飞行模式） |

### 3.3 URC 订阅（与真机一致）

guest 内先订阅再触发：`AT+CEREG=1`（注册 URC）、`AT+CGEREP=1`（+CGEV URC）。
未订阅时状态仍切换，只是不下发 URC。

## 4. 链路损伤 API 参考（集群）

传输：unix socket `p1/run/linkd.sock`；CLI：`python3 p1/cluster/link_ctl.py`。

| 请求 | 说明 |
|---|---|
| `{"cmd":"set","link":"link1","delay_ms":200,"jitter_ms":20,"loss_pct":5,"bw_kbps":1000}` | 对 link1 独立施加损伤（省略的参数保持不变） |
| `{"cmd":"clear","link":"link1"}` | 清除该链路损伤 |
| `{"cmd":"clear_all"}` | 全部清除 |
| `{"cmd":"status"}` | 每链路参数 + 双向计数器（in/out/drop） |

- 损伤**对称作用于双向**；两链路参数完全独立（互不串扰，验收见 28 号脚本）。
- `bw_kbps=0` 表示不限速；带宽用令牌桶实现（按字节计费，突发容量 0.5s）。
- 时延模型：`实际延迟 ≈ delay_ms ± jitter_ms`（每包独立随机，下限 0）。

## 5. AT 命令支持清单

| 类别 | 命令 | 备注 |
|---|---|---|
| 基本 | AT / ATE0 / ATE1 / ATI | 回显模式由 ATE 控制 |
| 身份 | AT+CGMI / CGMM / CGMR / CGSN / CIMI | CIMI 无 SIM 时报 +CME ERROR: 10 |
| SIM | AT+CPIN? / AT+CPIN= | 无 SIM → `+CME ERROR: 10` |
| 信号 | AT+CSQ / AT+CESQ | 与 set_signal 联动 |
| 注册 | AT+CREG? / CEREG? / CGREG? / CEREG= / COPS? / COPS=? | CEREG=<1/2> 开 URC |
| 数据 | AT+CGATT? / CGATT= / CGDCONT? / CGDCONT= / CGACT? / CGACT= / CGPADDR | 无网络时 +CME ERROR: 3 |
| 功能 | AT+CFUN? / CFUN=0 / CFUN=1 | 飞行模式联动链路 |
| URC | AT+CGEREP? / CGEREP= | +CGEV 开关 |
| 扩展 | AT+WMSTAT | 直读引擎状态 |

未知命令一律返回 `ERROR`；SIM/网络前置不满足返回对应 `+CME ERROR`。

## 6. 编写新测试用例

放置 `p1/tests/test_*.py`，使用 conftest 提供的工具：

```python
from conftest import at, guest, engine, curl_via_rndis, rndis_netif

def test_my_scenario(modem):                     # modem fixture: 结束自动恢复 normal
    modem.scenario("no_sim")                     # 切场景
    time.sleep(1)
    assert "+CME ERROR: 10" in at("AT+CPIN?")    # guest 内 AT 查询（自带重试）
    st = modem.status()
    assert st["sim"] == "absent"
    modem.scenario("normal")                     # 或依赖 fixture 兜底
```

可用工具：`at(cmd)`（自动重试，返回完整应答流含 URC）、`guest(shell 命令)`
（虚拟机内执行）、`engine(req)`（控制 API 原始调用）、`curl_via_rndis()`（绑蜂窝口
的 HTTP 探测）、`rndis_netif()`（蜂窝口名）。

注意事项：
1. 断网/弱网类用例必须把流量绑定到蜂窝口（`curl --interface` + 路由），
   否则管理口会"救活"流量造成假阴性；
2. URC 断言建议用 `inject_urc` + 下一条 AT 命令的应答流捕获（URC 先入缓冲）；
3. 场景切换后留 ≥1s 让 URC/状态传播；
4. 用例结束由 modem fixture 恢复 normal，无需手工清理。

## 8. 排错速查

完整 18 项"症状→根因→处理"表见 README §9。最高频三条：

1. **AT 不通/串口行为诡异** → 先查节点类型：`ls -l /dev/ttyUSB*` 必须 `crw`；
   普通文件 = 假文件遮蔽，`rm` 后重跑 `envctl.py provision`。
2. **RNDIS 网口消失** → 置备被跳过/失败：重跑 `envctl.py provision`；
   查 `readlink /sys/bus/usb/devices/1-1:1.3/driver` 应为 rndis_host。
3. **引擎/应答器连不上 AT 通道** → 二者互斥：`pkill -f wm_scenario_engine`
   后再起 responder，反之亦然（envctl 已自动处理）。

## 9. 已知限制（摘要）

- TCG 性能约原生 1/5~1/15；性能测试请用真机
- slirp 无 ICMP 出站（公网 ping 不通；网关 ping 与 TCP/UDP 正常）
- RNDIS 收包单包缓冲，大流量吞吐有限
- AT 通道单客户端（引擎与应答器互斥）
- 快照后引擎自动重连（对端不在快照内），约 2 秒自愈
- 接口 in 编号是被测软件的识别契约，改布局需同步
- Android 客户机与 GitHub Actions 真实流水线尚未验证
